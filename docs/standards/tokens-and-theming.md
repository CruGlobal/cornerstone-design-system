# Tokens & Theming — Focus Areas

Two token systems coexist. `packages/tokens` publishes `@cruglobal/cornerstone-design-system`: DTCG JSON in
three validated layers (`_ref` → `_sys` → `_cmp`), built by Style Dictionary into `--ref-*`, `--sys-*` and
`--cmp-*`, with consumers outside this repo, so its names are a contract (#121, #128). The component
library's themes live in `packages/components/src/styles/` as three cascade tiers (`cs-color-palette`,
`cs-color-variant`, `cs-theme`) that components read as `--cs-*`. **The two share no names.** The
destination is one generator deriving both from a brand's knobs; until then, every change is measured
against "adding a brand means adding a knob file and nothing else".

**Applies when the diff touches** `packages/tokens/**`,
`packages/components/src/styles/color/**`, `packages/components/src/styles/themes/**`, `layers.css`,
`size.styles.ts`, `variants.styles.ts`, `packages/components/tools/**`, or any line carrying `_ref`, `_sys`,
`_cmp`, `$value`, `--cs-color-`, `--cs-font-size`, `--cs-border-radius`, `--cs-form-control-height`,
`@layer cs-`, `.cs-theme-`, `.cs-light` or `.cs-dark`.

---

**The token package (`packages/tokens`)**

- `npm run validate` enforces: `_sys` aliases `_ref` only; `_cmp` aliases `_sys` only (`_cmp`→`_ref` warns,
  `_cmp`→`_cmp` errors); raw colour literals only in `_ref`. Do not re-flag what it checks. Review what it
  cannot: *which* alias was chosen (does this `_cmp` describe what the component does, or what the brand
  looks like), and whether the four `sys/<brand>-<mode>.json` files agree where they should.
- Bump levels: removing or renaming a `_sys` or `_cmp` token is **major**; adding a token, mode or
  component is minor; retargeting an alias that keeps the name is patch. The package is 0.x and `CLAUDE.md`
  names no pre-1.0 exception.
- Cru and FamilyLife, light and dark, are peers. Nothing in `_sys` assumes one is normal and the others are
  variants.
- `build.mjs` registers two transforms, `name/css/cornerstone` (strips the leading `_`) and
  `value/number/unit` (`px`, opacity ratio or `em` by path). A new category that needs a unit goes in
  `PX_CATEGORIES` or the transform, never as a string literal in the JSON.
- `/pull-tokens` syncs from Figma by per-subtree hash. A sync can reintroduce an alias that validates but
  is wrong (see the mined rules); read the resolved values, not only the alias legality.
- `libraries/` (the MUI adapter, `daisyui.css`, `cru-icons`) are consumer bridges. A value in them that is
  not emitted from `build/` by a script is a hand-copy that will drift.

**The library's themes (`packages/components/src/styles`)**

- Three tiers, each a cascade layer in `layers.css`: palettes (`color/palettes/<brand>.css`, named hues at
  eleven steps; raw values live here and nowhere else), variants (`color/variants/<role>.css` plus a
  generated `<brand>.css`, pointing a semantic role at a hue), and themes (`themes/<brand>.css`, roles onto
  usage plus every non-colour scale). Brand themes and variants are **generated by `tools/palette.mjs`
  from `tools/brands/<brand>.json`**; a hand edit to a generated file is a finding, and the fix is a knob.
- A component reads the role, never the hue:
  `var(--cs-color-fill-quiet, var(--cs-color-neutral-fill-quiet))`. A component stylesheet naming
  `--cs-color-blue-50` or a hex is a finding.
- `size` sets one `font-size` on the host; every inside dimension is `em`. Radius and border width are
  `rem`. A `px` dimension or a per-component size token breaks the ramp.
- The ramp is solved to WCAG luminance targets per step, not chosen: a knob is the input and a ramp never is,
  which is also why Figma cannot originate a palette.
- A knob change is finished when every brand regenerates and the diff has been read.
- A theme applies by class (`.cs-theme-cru`, `.cs-light`, `.cs-dark`) and classes cascade. A selector in a
  generated theme that adds a new mechanism is a generator change, not a CSS edit.

**The MUI adapter (`packages/tokens/libraries/mui`)**

Inline `sx` beats theme overrides, so the README states precedence. A change to the adapter's colour maps
without the script that emits them is a hand-copy (see the mined rules).

### Tokens Checklist

- Bump level matches (remove or rename `_sys`/`_cmp` → major): Yes/No/N/A
- The four `sys/*.json` modes agree on non-colour values, or the PR says why not: Yes/No/N/A
- No generated file edited by hand; the knob changed and every brand regenerated: Yes/No/N/A
- Components read a role, not a hue; dimensions in `em` and `rem`: Yes/No/N/A
- A fix for one context is a scoped role, not a global retune: Yes/No/N/A
- No `--cs-*` written into `packages/tokens`; no `--ref-*`, `--sys-*` or `--cmp-*` into `packages/components/src`: Yes/No/N/A

## Mined from merged PR history

Rules derived from 46 merged PRs (#49–#169). Each carries the PRs it came from.

- **Fix one context with a scoped role, never by retuning the shared role.** When `primary.default` or
  `<status>.default` fails in one mode or on one surface, add a scoped role in all four `sys/*.json`
  (`primary-strong`, `<status>-on-inverse`) aliasing the existing `_ref` where that mode already passes. The
  PR lists every `_cmp` alias of the shared role to show why the global change was rejected; a diff that
  darkens `primary.default` to fix one component is blocked.
  <!-- evidence: PR #50, #54 -->
- **Identical-pair aliases pass `validate` and render at 1.00:1.** In `sys/*.json`, reject any `on-<X>` or
  `<X>-outline` token whose `$value` resolves to the same `_ref` as its paired `<X>` or `<X>-container`.
  #50 fixed eight `on-<status>-container` and eleven `<status>-outline` tokens that aliased their own
  container; every alias was legal. Add the pair check to `scripts/validate-tokens.mjs` so a Figma sync
  cannot reintroduce it.
  <!-- evidence: PR #50 -->
- **The four mode files drift from each other and nothing catches it.** A non-colour `_sys` change (font
  family, weight, spacing, radius) in one `sys/<brand>-<mode>.json` changes the sibling mode identically in
  the same PR, or the body says why light and dark differ. `cru-dark` shipped body text in the display face
  and semi-bold body weights with zero validation errors; both surfaced only from a Figma hash diff.
  <!-- evidence: PR #56, #57 -->
- **No hand-embedded resolved value under `libraries/` without the script that emits it.** The MUI adapter
  says "regenerate the maps rather than hand-editing" while `scripts/` holds no generator; #50 retargeted
  `cru-light` secondary and `fl-light` on-danger minutes after #49 merged, and the adapter still embeds the
  old values, including a 1.82:1 danger pair with `contrastText` set so MUI's own fallback cannot rescue it.
  A PR adding to `libraries/` ships the generator and a check that the committed output matches it.
  <!-- evidence: PR #49, #50 -->
