Emit a brand's generated palette and theme as DTCG token files and a resolver.

`tools/tokens.mjs` writes `tokens/<brand>/` — `palette`, `roles`, `foundation` and `theme` token files, a DTCG resolver, and a Terrazzo config — from the same knobs and the same ramps that produce `src/styles/**`, in the same run. They are a second rendering of one source rather than a parallel definition, which is the only reason they cannot disagree.

The DTCG resolver spec turns out to map onto the cascade layers almost exactly: `sets` for the hue ramps, the role map and the mode-independent knobs, a `theme` modifier for light and dark. Terrazzo's `exclude` globs send each id namespace to its own stylesheet and its own `@layer`, and its `variableName` and `prepare` hooks reproduce the `--cs-*` names and the real selector lists — which the config takes from `SELECTORS()` in `palette-core.mjs` rather than repeating, since two copies of that list is how the generated CSS and the generated tokens would quietly stop landing in the same place.

**Not everything that defines a `var()` is a token.** A `--cs-*` declared from a literal or a single `var()` is a value or an alias; one declared from `calc()`, `color-mix()` or `oklch()` over other variables is a formula, and DTCG cannot express it. `--cs-space-m` is `calc(var(--cs-space-scale) * 1rem)` — the knob is the scale, and emitting the ramp as static values would throw away the runtime rescaling the library gets from it. Those are deferred: reported rather than emitted, and left as CSS. The count is part of the output, because a formula silently becoming a token is the regression this distinction exists to prevent.

Coverage against what ships today, verified by rebuilding through Terrazzo and comparing every declaration: palette 247 of 285, role map 104 of 112, mode-independent 32 of 121, light 71 of 75, dark 70 of 75 — **zero value mismatches**, with every remaining name a formula or an alias to one. Two textual differences are accepted as equivalent: Terrazzo writes `#fff` for `white` and quotes font-family names.

The stylesheets are still generated by `tools/palette.mjs` and are unchanged; nothing in the build consumes the token files yet.
