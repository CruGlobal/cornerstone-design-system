Cornerstone's work is organised into **efforts** — a body of work with a set of open questions attached to
it. This page is generated from the project's milestones when the site is built, so it describes what is
actually open rather than what someone last remembered to write down.

Each effort counts the questions still open inside it, and that number is not a progress bar. An effort with
**no open questions has not been asked yet** rather than finished, and an effort carrying many is one being
actively worked out. Once a question is answered it becomes work, and work reaches the
[changelog](/resources/changelog) when it ships.

Items named under an effort are the ones ready to be described publicly. The rest of an effort is
deliberation — the arguments that decide what gets built and why — and it stays in the
[repository's issues](https://github.com/CruGlobal/cornerstone-design-system/issues) rather than being
summarised here, because an unfinished argument reads like a commitment once it is written on a roadmap.

::roadmap

## Asking for something

This is not a request queue. If your team needs something that is not here — a component, an option on one
that exists, or a framework Cornerstone does not reach yet — [Support](/resources/support) is where to say
so, and describing the case you have to serve carries further than naming the API you would like.

A request does not become a roadmap item by being filed. It becomes one when the effort it belongs to has
answered enough questions for the thing to be worth building, which is the point at which it stops being a
question and starts being work. The issue you filed may well be closed before it appears here — the tracker
holds the project's open questions rather than its schedule, so a close there usually means the request has
been routed rather than refused.
